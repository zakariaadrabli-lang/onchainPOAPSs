Documentation

Learn how Onchain POAPs work

Overview

Onchain POAPs is a decentralized application for creating, minting, and distributing Proof of Attendance Protocol (POAP) badges on the Base Sepolia network. Each POAP is an ERC-721 token with custom SVG artwork stored directly onchain.

The smart contract is deployed at 0xC3249356a483fbe17d5355D39105D2eA666d9de6 on Base Sepolia (chain ID 84532).

Key Features

  • Create POAPs — Design custom SVG badges with metadata and register them onchain
  • Three Mint Types — Public, allowlist (Merkle proof), and signature-based minting
  • Soulbound Tokens — Optional non-transferable badges for true proof-of-attendance
  • Allowlist Tools — Client-side Merkle tree generation for gated events
  • QR Code Generator — Create physical posters with scannable mint links
  • Farcaster Mini App — Optimized display within Farcaster frames

Network Details

  • Network: Base Sepolia
  • Chain ID: 84532 (0x14a34)
  • RPC: https://sepolia.base.org
  • Explorer: https://sepolia.basescan.org

Soulbound POAPs

Soulbound tokens are non-transferable NFTs. Once minted to a wallet, they cannot be moved to another address. This ensures the POAP genuinely represents the holder's attendance at an event.

How It Works

When creating a POAP, the creator can toggle the Soulbound option. This sets a flag in the token's metadata that permanently disables the transferFrom and safeTransferFrom functions for that token.

Why Soulbound?

  • Authenticity — The holder actually attended the event
  • Anti-speculation — Badges cannot be traded or sold
  • Reputation — Build an onchain identity of verified attendance
  • Governance — Use POAPs for weighted voting in DAOs

Merkle Trees

A Merkle tree is a cryptographic data structure that allows efficient verification of large datasets. In Onchain POAPs, Merkle trees are used for allowlist-gated minting.

How It Works

  1. The organizer pastes a list of allowed addresses into the Allowlist Tools
  2. The tool computes a Merkle root — a single hash representing the entire list
  3. The root is stored onchain when the POAP is created
  4. Each allowed address receives a Merkle proof (a list of intermediate hashes)
  5. At mint time, the contract verifies the proof against the stored root

Benefits

  • Gas efficient — Only the root is stored onchain, not the full list
  • Privacy — The full list is never published onchain
  • Trustless — Proofs are verified cryptographically

Generating Proofs

Use the Allowlist Tools page to paste addresses and generate the Merkle root and individual proofs. Each proof is a comma-separated list of 32-byte hex values.

// Example proof format
0xabc123...,0xdef456...,0x789abc...

Signature Mints

Signature minting allows a POAP creator to authorize specific wallets to mint a POAP by signing a message off-chain. The signed message includes the POAP ID, recipient address, and a deadline.

37-Day Window

Signature mints support a time window of up to 37 days. After the deadline, the signature becomes invalid and the recipient can no longer mint. This prevents stale authorizations from being used indefinitely.

How It Works

  1. The creator signs an EIP-712 typed message containing the POAP ID, recipient, and deadline
  2. The signature and deadline are shared with the recipient (e.g., via QR code)
  3. The recipient submits the signature to the contract's mintSignature function
  4. The contract recovers the signer address and verifies it matches the POAP creator
  5. If the deadline has not passed, the mint succeeds

QR Integration

Use the QR Signature Generator page to create signed mint URLs and downloadable QR codes for physical posters at events.

SVG Artwork Rules

All POAP artwork is stored as inline SVG directly onchain. This ensures the artwork is permanently accessible without relying on external servers or IPFS.

Requirements

  • Format: Valid SVG XML (must start with <svg)
  • Size: Maximum 100KB per SVG
  • ViewBox: Required — recommended viewBox="0 0 200 200"
  • No external references: All content must be inline (no external images, fonts, or CSS)
  • Self-contained: All styles and definitions must be within the SVG

Best Practices

  • Use <defs> for gradients and patterns
  • Keep paths simple to minimize onchain storage cost
  • Use system-safe fonts or convert text to paths
  • Test your SVG renders correctly before submitting

Example SVG

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 200 200">
  <defs>
    <linearGradient id="g" x1="0" y1="0" x2="1" y2="1">
      <stop offset="0" stop-color="#00d4ff"/>
      <stop offset="1" stop-color="#b14cff"/>
    </linearGradient>
  </defs>
  <circle cx="100" cy="100" r="90" fill="url(#g)"/>
  <text x="100" y="110" text-anchor="middle"
    fill="white" font-size="24" font-family="sans-serif">
    POAP
  </text>
</svg>

Farcaster Mini App

Onchain POAPs can run as a Farcaster Mini App (Frame). This allows users to discover and mint POAPs directly within the Farcaster social ecosystem.

How to Enable

  • Toggle the Farcaster mode in the header to switch to the frame-optimized view
  • The app automatically detects when loaded inside a Farcaster frame
  • The Farcaster mode shows a banner and adjusts the layout for frame display

Frame Meta Tags

The page includes fc:frame meta tags that Farcaster clients use to render the frame preview. When a user taps the frame button, it opens the full app in a webview.

Use Cases

  • Share POAP mint links as Farcaster casts
  • Event organizers can distribute QR codes via Farcaster
  • Users can showcase their POAP gallery in their Farcaster profile
